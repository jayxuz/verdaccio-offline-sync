## 方法与隔离

目标为 SSH 已授权 自用服务器，沿用认证与严格主机检查。固定现有镜像 `${TEST_IMAGE}`，Node 22.21.1、Verdaccio 6.2.4。每个主性能容器限 0.75 CPU、1536 MiB 内存（memory-swap 总额同为 1536 MiB，不额外使用 swap）、160 PID、设备读取 15 MiB/s，rootfs 只读、无 capabilities、no-new-privileges、日志 2 MiB×2。真实缓存只以 `${PACKAGE_CACHE_ROOT}:/real-cache:ro` 挂载；插件 build 和脚本也只读。旧 LocalDatabase 接到独立测试 state，测试子类仅将包读取路由至真实只读目录；没有为产品新增其他包路径配置。

主性能实例均 `--network none`，没有发布端口、uplink、代理或外部访问；HTTP 只监听各自容器回环。`/tmp` tmpfs 256 MiB、`/work` 512 MiB、独立具标签 state volume 192 MiB；索引默认预算 64 MiB/4096 条，内存 metadata 16 MiB/64 条、SHA1 2048 条。基线与候选依次运行，未并行压测。真实磁盘补测只写本任务 `/tmp/verdaccio-readcache-20261015-91b7cf/disk-state`，索引预算 2 MiB，主文件实测 532480 字节，未复制真实缓存。

同步 A/B 使用独立 tmpfs、0.5 CPU/512 MiB 限额及本任务 `--internal` 网络，没有挂载生产数据。该 Docker 的内部网络未实际发布所请求的回环端口，原映射失败证据单独保留；没有重启实例，改由主机访问内部桥接地址运行正式同步验收。无 LAN 端口开放、防火墙修改或生产网络修改。

这里的“冷”是 Node 进程及插件状态冷，不是 OS 页缓存冷。未执行 drop_caches，冷样本 `/proc/self/io` 的 read_bytes 为 0；逻辑 tarball 完整哈希字节另行计数。主持久状态为有界 tmpfs，额外真实文件系统补测 SQLite FULL 同步开销。不同 Node 子进程保留同一 namespace 和状态；跨容器 namespace 检查另做，未混为保留索引收益。客户端每次使用新的 store/cache/project，结束后删除，安装脚本关闭；服务器客户端阶段先预热四个安装包，不能据此声称所有冷客户端场景均已覆盖。

## 首次请求和准备成本

TypeScript 的 39 个本地 tgz 合计 309762632 字节，每轮冷请求均完整读取并 SHA1。三轮结果（毫秒）：

| 条件 | 三次观测 |
|---|---|
| 基线新进程 | 6282 / 6205 / 6522 |
| 候选空持久索引新进程 | 6581 / 6522 / 6701 |
| 候选保留索引的新进程 | 196 / 185 / 296 |
| 候选显式预热后的首次请求 | 114 / 74 / 80 |
| 预热准备时间 | 25978 / 25720 / 25213 |

冷请求中位数增加约 4.8%，真实缓存 stat 次数由 199 增为 241。保留状态首次请求命中 1 份持久 metadata，tarball 哈希字节为 0，但仍做 84 次全身份检查；预热后的首次请求也为 0 哈希字节。预热明确选取 typescript、并发 1、速率 16 MiB/s，实际 metadata 和 tgz 都纳入限速；25–26 秒准备时间必须计算，不能把 80ms 当作总成本。

共享原状态卷但更换 namespace 后，观察到 40 次 namespace 失效，重新读取全部 309762632 字节，首次请求 6603ms。这是安全冷启动，不是容器重建后自动延续的性能收益。

## 小配额、前台优先与取消

先以 100 个只含约 8 KiB description 的合成 metadata 填满 2 MiB 索引逻辑配额，触发真实淘汰，再加入 @types/node 的 228 个多版本哈希。大 metadata 无法整份装入该小配额，故新进程复用哈希但仍重建 metadata。间隔超过 5 秒以触发 LRU touch，重复三轮。

真实磁盘三次请求 1574/1518/1518ms，均持久命中 228 个哈希、0 字节 tgz 哈希读取、2 个事务；并非 228 次同步写。数据库 532480 字节、254 行，淘汰查询计划使用 entries_eviction 索引。tmpfs 同条件为 1612/1529/1237ms，也各 2 个事务。SQL 只导出计数、配额与查询计划，没有归档真实派生 metadata 数据库。

真实磁盘事件循环 P95 70.8–90.5ms、P99 701–771ms，表明大原始 metadata 解析与重建仍可阻塞事件循环；持久哈希命中没有消除这一成本。不能将 FULL SQLite 的批量事务优化宣传为没有阻塞。

在 force TypeScript 后台工作期间连续读取已热 lodash 30 次，中位数 12.7ms、P95 91.9ms、P99 92.3ms；比普通候选 lodash 热态 P95 70.9ms 更高。后台被前台抢占，记录为 preempted、completed 为空，没有冒充预热完成。显式取消观测约 557ms（含 100ms 轮询粒度及调度），实现具有 500ms 终止兜底，不能承诺墙钟绝对小于 500ms。
